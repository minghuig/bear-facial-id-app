# Tracer implementation

The API owns the shared collection. PostgreSQL persists batches, photos, raw detections, head observations, embeddings, bears, reviews, immutable suggestion snapshots, jobs and attempts. There is no user identity or inferred reviewer attribution.

Upload hashes original bytes and saves both original and EXIF-oriented PNG in private S3. Exact duplicate uploads return the existing photo. Invalid batch members fail independently. A detection job receives original/oriented keys, oriented image dimensions, a short-lived signed GET URL, pipeline and attempt token. It returns every detector box and score. The API applies the fixed threshold and clipped floor/ceil rule, writes accepted PNG crops and observations in the result transaction, and stops. API-owned crop persistence keeps the coordinate/crop rule shared between adapters. It does not run ML. This is a deliberate refinement of the plan's worker crop-output contract: accepted crops are generated by the result handler from the oriented source and returned via persisted head records.

Recognition is queued only by the explicit endpoint. Ignored and unusable heads are skipped. Each returned head independently stores either a valid normalized 512-vector or a failure. Successful heads survive another head's failure and are not recomputed by retry. Recognition computes exact cosine retrieval against confirmed usable references in the same pipeline, excluding the original photo. The top ten reference sightings are kept independently, so multiple photos of the same bear can appear. The gallery revision lock serializes reviews and snapshot creation. Older snapshots retain names, scores and reference IDs as seen at that time, even after corrections.

Jobs use PostgreSQL row locks with SKIP LOCKED, expiring leases, attempt tokens, heartbeats, three automatic attempts and a 30-minute hard lease limit. Expired work is reclaimed during worker polling. Duplicate successful result submission returns success; stale attempts cannot replace newer results. A detection retry retains old attempt history. Recognition retry makes a new job containing only unfinished eligible heads. Database commits determine pause/review persistence independently of the browser. Object writes precede the transaction and use deterministic keys, so replay overwrites the same crop key; a crash can leave an unreferenced object, never an auto-confirmed identity.

The API has no ML imports. The explicit test-only mock stack uses known filename prefixes: `multi`, `no-head`, `fail-detection` (fails first attempt), `partial` (one crop fails), `different` (orthogonal identity), and `first`/`later` (matching features). These are deterministic synthetic fixtures, not a development inference mode or predictions. Mock data has a separate pipeline and production refuses mock configuration.

Real worker processes run only on AWS x86 Linux. Each job gets a short-lived model subprocess under a shared file lock so detector and recognition model allocations do not overlap. The legacy detector and newer ReID environments remain separate. Every checkpoint is verified against trusted SHA-256 before deserialization. The pipeline namespace hashes model hashes, adapter source, vendored source, preprocessing and image dependency definitions.

Development access is a loopback API, reached via SSM port forwarding in AWS. The local Vite proxy forwards /api to this tunnel. Images travel through the same tunnel; workers get expiring S3 URLs and separate credentials. No public API listener, S3 public access, frontend secrets, or account screens are needed.
